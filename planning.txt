  Investigation Findings: Root Cause Analysis

  Executive Summary

  The investigation reveals a design mismatch between prompt-level guidance and
  backend enforcement mechanisms. The LLM is not "dumb" — it's simply operating
  without hard guardrails because backend limits are set to effectively
  unlimited (999).

  ---
  Primary Root Cause: Backend Limits Disabled

  From .env:
  MCP_MAX_TOOL_ITERATIONS=999     # Should be ~10
  MCP_MAX_SEARCHES_PER_TURN=999   # Should be ~2
  RAG_MAX_CHUNK_READS_PER_TURN=999
  RAG_MAX_CHUNK_PAGES_PER_TURN=999

  Why this matters: The backend has a hard-stop mechanism in types.py:192-207:

  def reserve_search(self) -> None:
      effective_limit = self._effective_max_searches  # Reads from 
  MCP_MAX_SEARCHES_PER_TURN
      if effective_limit <= 0:
          self.searches_used += 1
          return  # ← No enforcement when limit is 0 or negative

      self.searches_used += 1
      if self.searches_used > effective_limit:
          raise SearchBudgetExceeded(...)  # ← Never fires when limit is 999

  When budget is exceeded, the orchestrator (orchestrator.py:1222-1236) would
  return a hard stop with explicit guidance:

  if remaining_searches == 0:
      policy_tool_result = {
          "status": "blocked",
          "error_code": "search_budget_exceeded",
          "hint": "Use the snippets already retrieved... call read_document 
  using existing snippet IDs"
      }

  With limits at 999, this feedback mechanism NEVER fires.

  ---
  Secondary Root Cause: Prompts Are Soft Guidance Only

  The agentic prompt in agentic_prompts.py:47-49 says:

  4. **Retry once if needed**: Only run a second search if the first search is

   retry...

  But LLMs are probabilistic — they follow guidance ~80-90% of the time, not
  100%. The backend enforcement is the hard stop that catches the other 10-20%.

⏺ Proposed Architecture: Tool-Boundary Agentic Control

  The Core Problem with the Current Design

  Your orchestrator currently has two voices talking to the LLM simultaneously:

  Voice 1: System Prompt     → "Here's how to behave"
  Voice 2: Injected Notes    → "Actually, ignore that, do this instead"

  Every injected system message during the tool loop (evidence_summary_note,
  tool_loop_note, reminder) is a second voice that competes with the system
  prompt. The LLM has to reconcile conflicting authorities on every iteration.

  ---
  The Anthropic Principle: One Voice, Smart Tools

  The modern agentic pattern is simple:

  The system prompt is the constitution. It is never contradicted. All runtime 
  feedback flows through tool responses, not injected system messages.

  ┌─────────────────────────────────────────────────┐
  │              SYSTEM PROMPT                       │
  │         (single source of truth)                 │
  │                                                  │

  │    you with structured feedback."                │
  │                                                  │
  │              NEVER CONTRADICTED                  │
  └────────────────────┬────────────────────────────┘
                       │
                       ▼
                ┌──────────────┐
                │     LLM      │ ← Sees ONE consistent instruction set
                │   Decides    │
                └──────┬───────┘
                       │
                       ▼
           ┌───────────────────────┐
           │    Tool Boundary      │ ← ALL guardrails live HERE
           │                       │
           │  • Validates input    │
           │  • Enforces budgets   │
           │  • Detects duplicates │
           │  • Returns structured │
           │    feedback + hints   │
           └───────────┬───────────┘
                       │
                       ▼
                ┌──────────────┐
                │     LLM      │ ← Reads tool feedback, adapts
                │   Adapts     │
                └──────────────┘

  No injected system messages mid-loop. No second voice. The tool response IS
  the guidance.

  ---
  What Changes

  1. System Prompt: Clean Constitution

  One prompt. No ambiguity. No conditions that can be interpreted multiple ways.

  ## Tools

  ### search_knowledge(queries, query)
  Discovers what exists in the knowledge base. Returns metadata + char
  estimates.
  - Use `queries=[...]` to batch multiple sub-questions in ONE call.
  - Each result includes `char_estimate` — use this to plan your read budget.

  ### read_document(ids, max_chars)
  Gets full content by ID. Returns content OR partial results with guidance.
  - Set max_chars ≥ sum of char_estimates for your selected IDs.
  - If budget is tight, the tool will read what fits and tell you what was
  deferred.

  ## Workflow Rules

  1. ONE search per intent. The tool will reject duplicate intents
     and return your earlier results.
  2. ONE read per search. Batch all IDs into a single read_document call.
  3. If read returns deferred items, you may do ONE follow-up read for those.
  4. Moving to a genuinely new topic (e.g., complaints → products)
     counts as a new intent — you may search again.
  5. Tool responses include a `budget` object showing your remaining
     allowances. Plan accordingly.

  ## What the tools will tell you

  - If you repeat a search intent → tool returns your earlier results + hint
  - If you exceed read budget → tool returns what fits + deferred list
  - If you approach turn limits → tool responses include warnings
  - Trust the tool feedback. It is your ground truth.

  That's it. No "retry once if off-topic." No ambiguity. The tools handle
  enforcement.
