# Docs Refresh Plan (2026-02-02)

## Plan
1) Audit code/docs for current state
2) Refresh active READMEs and core docs
3) Archive or remove outdated docs
4) Update business brief at end
5) Run consistency sweep and review

## Business POV
### Scenario 1 — New engineer onboarding
- **Today:** Conflicting docs slow onboarding and cause misconfigurations.
- **After:** One clear docs index + updated READMEs guide setup in minutes.
- **Success:** Faster time-to-first-run, fewer “which doc is correct?” questions.

### Scenario 2 — Support/ops validating MCP behavior
- **Today:** Tool surface confusion (legacy table tools vs agentic tools) leads to wrong QA expectations.
- **After:** Agentic tool surface explicitly documented; legacy tools clearly marked backend-only.
- **Success:** QA runs align with actual tool allowlist; fewer false bug reports.

### Scenario 3 — Integrations + email connectors
- **Today:** Unsure if email connectors are live or experimental; unclear sync cadence.
- **After:** Email connectors marked live + safe-send policy clarified; integrations scheduling guidance updated.
- **Success:** Fewer support escalations about missing send behavior; fewer misconfigured syncs.

### Scenario 4 — Voice + mobile expectations
- **Today:** Stakeholders assume voice/mobile are production-ready.
- **After:** Voice is labeled dev-only; mobile docs archived.
- **Success:** Reduced roadmap confusion and incorrect deployment plans.

### Scenario 5 — Product brief clarity
- **Today:** Business brief drifts into technical details and beta status is unclear.
- **After:** Business-only brief with beta positioning and current product scope.
- **Success:** Sales/investor conversations stay aligned with reality.
